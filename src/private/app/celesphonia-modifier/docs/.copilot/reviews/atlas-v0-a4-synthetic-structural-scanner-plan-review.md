## 3. Accepted scope

The accepted A4R1 increment:

- scans one valid in-memory A3 result under a closed document role;
- uses iterative deterministic containment traversal and never follows reference targets;
- emits one detached immutable observation per materialized graph occurrence;
- identifies ordinary members only by per-object occurrence ordinal and arrays by element index;
- emits no scalar values, property names or equality, opaque class strings, raw identity numbers,
  source data, paths, hashes, aliases, or content-derived labels;
- reconciles typed locators, container closure, references, and scanner census against released A3
  token and graph censuses;
- provides one strict bounded canonical in-memory contract and schema; and
- validates completeness with exact synthetic expectations, an independent syntax-based oracle, and
  mutated-document rejection without production fault injection.

A4R1 adds no CLI, filesystem, snapshot integration, persistence, private-corpus operation,
multi-input aggregation, semantics, editing, or writes. Historical content-derived aliases and gap
records are not reused.

## 4. Threat model and review boundary

The accepted environment trusts the local user, administrator, checkout, runtime, and selected
binaries. Controls address credible scanner correctness, completeness, privacy leakage,
nondeterminism, malformed contract handling, practical resource bounds, cancellation, regression,
and maintainability defects.

Malicious-owner substitution, runtime Git or binary attestation, authorization ceremony, document
SHA graphs, r1/r2 state, persistent protocol state, and A5 private-corpus governance are out of scope.
Review prefers a narrower claim and simpler scanner over additional ceremony.
