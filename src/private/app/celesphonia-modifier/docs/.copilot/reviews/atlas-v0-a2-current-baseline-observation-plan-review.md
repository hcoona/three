## 3. Accepted boundary

The final plan:

- keeps A2R9 blocked because prior request identity is unavailable;
- observes only current state under `trusted-local-filesystem/v1`;
- fingerprints each document successfully returned before or during its terminal stage;
- makes no historical-request or simultaneous-filesystem-snapshot claim;
- uses released strict readers and only the released inventory-transition predicates;
- validates canonical input paths and ordinary non-reparse components;
- uses one disposable session-only C# project and one private create-new report;
- allows retry after host or report-write failure because no consumable authority exists;
- emits only a fixed signal and starts no process from observer code;
- reads no wrapper, live source, game, save, definition, executable, copy, or publication content;
- changes no production, test, schema, package, tracked project, or CLI code; and
- authorizes no discovery, repair, confirmation, copy, cleanup, or existing-input write.

The plan deliberately excludes held-handle protocols, one-shot gates, invocation journals, runtime
Git hermeticity, process containment, hostile-local defenses, and result-indistinguishability.
Those mechanisms are not required by the accepted claim or threat model.
