## 3. Planning-drift gate

Before each correction, the candidate was checked against the project-leader-approved minimum:

- A0R3 remains closed and consumed; A0R4 is a new increment and never reads A0R3 state;
- one new marker permits at most one current read-only replay;
- the exact qualified A0R3 source supplies technical derivation, not continuing authority;
- the approved manifest remains sole corpus-specific authority and a new protected locator remains
  runtime input only;
- existing outer gates and typed pipeline boundaries map mechanically to fixed result classes;
- candidate construction and replay remain memory-only, with all staging and final publication deleted;
- no dynamic result, private cause, private detail, or exception reaches output or Git;
- internal, ready, and incomplete outcomes do not overclaim a refusal boundary;
- no A0R2-style decision/census branch, candidate decision, A2, A3, or original-data write occurs; and
- every consuming branch closes result-safely and returns to a separate plan.

The final plan adds no new diagnostic architecture, corpus policy, approval process, private format,
threat model, or hostile-local defense. Its durable marker, receipt, exact source gate, and fixed
classes are the minimum controls needed to make one privacy-safe observation reproducible and
non-retryable.

After verified shared `R0R4`, work may:

1. create a new protected A0R4 workspace containing only the exact qualified A0R3 project and source
   bytes plus an empty state directory;
2. modify only copied project and source to implement the reviewed A0R4 plan;
3. format, rebuild twice, run the complete synthetic suite, and prove qualified output byte stability;
4. create the exact immutable source-binding document;
5. independently review the complete exact source, project, binaries, synthetic tests, and binding until
   `No findings`; and
6. author and independently review the result-safe `S0R4` source-qualification record.

Neither `P0R4` nor `R0R4` authorizes creating or reading the runtime-locator document, reading the
historical request or manifest, reading current roots or current-tree metadata, publishing a marker or
receipt, diagnosing, publishing a candidate, correcting source from private evidence, or performing an
A2, A3, production, or original-data operation.

Only verified shared `S0R4` may authorize locator materialization and one consuming read-only
diagnostic. A pure preflight refusal before any marker or private read may be corrected and reinvoked
with a fresh run ID. Any complete, partial, or zero-byte final marker consumes the attempt.
