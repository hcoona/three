## 1. Problem, adjudication, and minimum shape

A0R6 completed at verified shared `G0R6` with
`historical-definition-policy-refused`. Its complete canonical marker and matching receipt consumed all
A0R6 private-read authority. The fixed class establishes only that the ordered pipeline reached but did
not complete `ManifestDefinitionPolicy`; it identifies no private cause, path, rule, value, difference,
or individual predicate.

The qualified A0R6 pipeline had already completed these earlier boundaries:

1. `InputAccess`;
2. `RequestDocument`;
3. `ManifestDocument`;
4. `RequestValues`;
5. `AnchorBinding`;
6. `ManifestEnvelope`;
7. `ManifestReasonCode`; and
8. `ManifestSavePolicy`.

The final historical boundary then reapplied the current definition glob matcher to every stored
historical definition path and required the first current match to equal the stored group and decision.

Repository-safe ideal-first and adversarial adjudications independently reached the same conclusion,
and the project leader approved it:

| Concern                             | Correct authority                                          |
| ----------------------------------- | ---------------------------------------------------------- |
| Exact identity and integrity        | Request SHA-256 over the original approved raw bytes       |
| Authorization and provenance        | Exact approval envelope and original A0 decision reference |
| Rule grammar and document structure | Strict released `atlas-intake/v2` validation               |
| Historical entry mapping            | Exact approved group, order, decision, and entry fields    |
| Current matcher compatibility       | Future mandatory live definition reconciliation            |
| Current tree membership             | Future complete metadata-only definition enumeration       |

The historical replay checks one real but misplaced property: whether today's matcher reproduces the
approved classification for the finite historical path set. It does not establish identity, approval,
historical producer correctness, behavior for new paths, or current-tree membership. Making it a
historical acceptance condition gives an evolving implementation a second veto over unchanged approved
bytes.

This is not a claim that rule semantics are unimportant. Ordered first-match matching remains mandatory
when a future current tree is reconciled against the approved rules. That live gate is stronger because
it checks the complete observed definition denominator, rejects missing and novel paths, and compares
each current classification with the approved mapping before content access.

A0R7 is therefore the minimum correction:

- partially supersede only the historical current-matcher replay requirement;
- accept the exact approved definition mapping as historical authority;
- retain every completed A0R6 identity, strict-reader, approval, reason, and save-policy conclusion;
- retain strict definition grammar and internal consistency in the released v2 reader;
- perform no private replay, subgroup diagnosis, source implementation, or current-tree operation; and
- close the corrected historical authority question through reviewed repository-safe records only.

## 2. Exact authority correction

For the immutable approved revision-3 manifest, historical definition authority is the conjunction of:

1. the exact original manifest bytes;
2. the matching request SHA-256 and public game identity;
3. strict `atlas-intake/v2` parsing;
4. exact survey alias and manifest revision;
5. `manual-a0` validation with every reconciliation flag true;
6. exact approved confirmation, project-leader role, and original decision reference; and
7. the stored ordered groups, selection rules, group counts, entries, group references, and decisions.

The released strict reader already rejects:

- invalid definition-group identifiers;
- invalid selection-rule grammar;
- duplicate group identifiers, source aliases, or normalized relative paths;
- negative or inconsistent group counts;
- entries that name an absent group;
- invalid entry or group decisions;
- entry decisions that differ from their stored group decision;
- non-file or reparse-backed entries;
- inconsistent manifest-level definition counts; and
- false definition-count, role/decision, or group-membership reconciliation flags.

The exact digest-bound approval makes the stored mapping normative historical evidence. The historical
consumer must not independently require that a later matcher implementation reconstruct that approved
mapping.

A0R7 removes only that extra historical replay. It does not weaken:

- exact-byte identity or request digest equality;
- strict JSON, versioned schema, bounded parsing, or rule grammar;
- manifest alias, revision, validation, confirmation, role, or decision reference;
- reason-code grammar;
- save-root or save-entry structural consistency;
- the completed A0R6 save role, slot, and decision result;
- stored definition group order, rules, counts, entries, mappings, or decisions;
- canonical rules for newly generated control or corpus documents; or
- future fail-closed live definition matching and denominator reconciliation.

There is no alternate reader, historical matcher, known-digest exception, normalized representation,
fallback, migration, manifest rewrite, copied approval, or new approval.

## 5. Future live reconciliation boundary

The later current-corpus plan must preserve the approved definition semantics while applying them to a
fresh current tree:

- the approved manifest supplies ordered selection rules, group identifiers, and decisions;
- the current matcher applies those rules to every observed definition file;
- both save roots and `Game.exe` are excluded from the definition denominator before recursion;
- missing, novel, reparse-backed, unsupported, duplicate, or case-colliding definition paths refuse;
- every observed definition path must retain its approved group and decision; and
- no definition content is opened before metadata-only reconciliation completes.

Matcher behavior remains versioned production protocol. A deliberate semantic change requires a new
contract and appropriate approval; it must not be hidden behind a historical compatibility branch.

### 5.1 Separate mutable save domain

Nested save roots are a separate mutable runtime domain, not part of the immutable game-definition
denominator. A future current-corpus plan must not preserve the old exact save-entry denominator
coupling.

The approved manifest may continue to supply save-root roles, root aliases, filename classification
policy, and stable aliases where an approved locator identity still exists. It is not authority for the
current save-file membership, count, content, or continued existence of a historical save.

Future save handling must:

- enumerate each save root independently from the definition tree;
- treat observed save membership and counts as a fresh mutable snapshot;
- classify current save filenames under the approved save policy;
- allocate or preserve aliases under an explicitly reviewed rule;
- keep save changes from invalidating the game-definition baseline; and
- define snapshot stability and candidate behavior in that future plan.

This section constrains future planning only. It authorizes no current-tree or save access under A0R7.
