## 1. Repository-safe facts and authority decision

The first exact A0R1 metadata census ran under verified shared `R0R1`, selected the governing plan's
safe-refusal branch, and published no candidate or partial artifact. That refusal consumed A0R1
private-run authority.

Afterward, source-review drift was found: one compound finding had incorrectly treated ordinary
matching directories as definition candidates, contrary to released file-only selection semantics.
The finding was made atomic:

- device- or reparse-backed required traversal remains a TP and a refusal; and
- ordinary matching directories are traversal nodes, so the matching-directory part is FP.

Independent review concurred with the FP. The session utility was corrected and independently
reviewed. A second metadata census was then executed without first persisting a new authority plan.
That second execution exceeded A0R1 authority.

The second result:

- is not A0R1 acceptance evidence;
- does not authorize a candidate, decision, final manifest, diagnosis, or retry;
- must not be used to infer any private fact or failure cause; and
- cannot be retroactively approved.

The project leader explicitly authorized this remediation and a later A0R2 plan. This remediation
does not approve the overrun; it records, contains, and prevents reliance on it.

## 2. Accepted A0R1 closure

A0R1 closes only on its first authorized safe-refusal branch. Its completion record must state:

- exact `P0R1` and `R0R1` authority;
- the first authorized fixed-output refusal and absence of a candidate or partial publication;
- no candidate decision, `D0R1`, final manifest, final-byte approval, or A2 operation followed under
  authority;
- the later authority overrun occurred and is excluded from acceptance evidence;
- the latest corrected source remains non-authoritative for private execution until A0R2;
- no private stage, cause, path, filename, count, entry, difference, content, or corpus hash is
  disclosed; and
- A0R1 grants no continuation authority.

The completion record may bind repository-safe utility source and assembly hashes only to identify
the preserved technical starting point. It must not describe the second execution's result as an
accepted branch, validation, retry, or proof.

## 4. Planning-drift and TP/FP correction

The remediation records two separate governance findings:

1. **matching-directory review finding - FP:** released Atlas handles ordinary directories before
   rule matching and emits only file candidates. Requiring a matching ordinary directory to refuse
   changed authority and could block valid recursive rules. The planned independent plan review must
   explicitly concur or return a finding.
2. **post-refusal second execution - TP:** A0R1 defined safe refusal as terminal and authorized one
   metadata census. Correcting Git-ignored utility source did not create new private-run authority.
   The second execution therefore cannot contribute acceptance evidence.

The proportional corrections are:

- restore released file-only traversal semantics in the preserved technical source;
- do not rewrite history or erase the execution fact;
- narrow A0R1 acceptance to the first authorized refusal;
- publish explicit governance closure before any new plan; and
- require A0R2 to bind the latest source and grant any future private-run authority prospectively.

No additional runtime control is required in A0R1C1 because it authorizes no runtime.

## 7. A0R2 handoff

After verified shared `G0R1`, a plan-only A0R2 may bind the latest corrected session source as its
technical starting point. Because a blind repetition would not explain the first authorized refusal,
A0R2 must define and require before granting any census authority:

1. one reviewed privacy-safe fixed-stage diagnostic over the existing metadata-only pipeline;
2. exact result classes that disclose no corpus payload;
3. a project-leader gate after the protected diagnosis;
4. source correction only when the result proves an implementation defect within unchanged A0
   policy;
5. complete independent source review and fresh source/assembly bindings; and
6. at most one prospectively authorized metadata census after those gates.

A0R2 must stop and return to planning if diagnosis indicates a policy change, ambiguous
classification, unreadable or unsupported selected entry, private disclosure risk, source-content
need, or any change to the accepted threat model.

This handoff creates no A0R2 execution authority by itself.
