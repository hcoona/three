enter it independently with the granted historical-request SHA-256. In this order the ingress must:

1. require the derived request and authority paths to be ordinary non-reparse files on a ready fixed
   local drive;
2. read the exact request bytes, compute SHA-256, and require equality with the granted protected

   consequential/inert behavior, then require the exact schema, lowercase digest shape, integer

## 9. Mechanical discovery, separate copy, and qualification

Current matching is mandatory only during complete live definition reconciliation. Historical ingress
never calls it.

For each reconciliation, traversal starts at the request-bound definition root and builds one complete
metadata-only inventory. Root-relative paths normalize separators to `/` and use ordinal identity.
Before attribute inspection or recursion, compare the candidate root-relative path case-insensitively
against exactly:

```text
Game.exe
save
www/save
```

An excluded candidate is skipped immediately. The parent enumeration inevitably observes that entry
path, but the operation performs no existence probe, attribute read, content open, child enumeration,
or output for the excluded path. Exclusions need not exist. No descendant of an excluded directory
enters the denominator.

For every other entry, traversal inspects only metadata needed to establish ordinary file/directory
type, reparse status, relative path, and recursion. It rejects unreadable, unsupported, reparse-backed,
duplicate, case-colliding, escaping, or changing entries. It applies the current ordered first-match
definition rules to every observed file and records one terminal group and decision.

Exact reconciliation requires both directions:

- every stored historical definition entry has exactly one current file with the same normalized
  relative path, source alias, ordered group, and terminal decision; and
- every current definition file has exactly one stored historical entry with those exact values.

Group counts and total included/excluded counts must equal the frozen definition view. Missing, novel,
rebound, differently grouped, differently decided, unsupported, or ambiguous membership is a safe
refusal. The operation reports no differing path or count.

Discovery strictly validates the exactly empty bootstrap inventory, request, and separate authorization
binding; an empty inventory is valid only at this pre-discovery boundary. It then independently
re-derives the historical request and authority paths and enters frozen ingress with the granted
request digest. Before traversal it requires exact typed equality between the ingress view and
discovery request for the five ingress-derived active values: historical-authority digest,
historical-authority revision, survey alias, integer `applicationId`, and integer `buildId`. It
separately requires the discovery request's canonical definition root to equal the exact granted
authorization field. It performs two separately constructed complete reconciliations; each must equal
the historical view and each other exactly. Only then does it mechanically derive the root map and
included-only copy plan, resolving every plan alias/path relation from that in-memory authority view and

## 10. Inventory, publication, and one logical attempt

inventory entry has a legacy-authority class, legacy-document role, legacy-authority alias or lineage,

exact in the in-memory view and are never reallocated as authority-document aliases. Destination

The run identifier permits one create-new authorization candidate and one closed local grant decision.

enumeration or content capture after valid state r2. A valid not-granted path forbids final
authorization and every private evidence operation.

If a safe refusal occurs before a durable marker can be published, runtime cannot prove that a later
invocation is a retry. This limitation is not represented as runtime enforcement. Governance consumes
