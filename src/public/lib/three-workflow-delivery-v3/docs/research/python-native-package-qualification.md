# Native Python Package Qualification Protocol

This record defines the finite local package experiment for the accepted
[execution contract](../middle-level-design.md#native-python-package-execution).
It is a protocol, not a runtime result. Its delivery PR must independently review
and protect this exact protocol and executable packet before the first launch.
The existing Python callers remain active until complete qualification and cutover.
The original packet below is spent. The [first fresh diagnostic](#first-fresh-diagnostic)
binds the separately prepared subject for the next launch; it cannot reuse the
original failed lifetime.

## Question and Scope

Determine whether the protected private application's four adopted Python package
checks compose frozen UV preparation, maintained Hatchling/nbgv-python metadata,
complete original wheel/sdist outputs, payload inspection, clean original-wheel
installation/import and a Git-free original-sdist build/install/import. Qualify
this Linux integration only, not full Python impact planning, root pytest member
preparation, caller cutover, Release, arbitrary Python backends or Windows.

consumes one original native metadata response and one maintained backend identity

It produces the complete four-check partition with candidate equal to basis; this
isolates execution, not changed-commit impact completeness. No workspace roster,
backend requirements, UV resolver, group semantics or version engine is copied.

The accepted contraction Wave permits isolated builds/tests, credential-free
adapter validation and tool/dependency preparation. This distinct finite local

independent engineering/OCR, record/research review and protected merge. It does

## Recipe and Native Responsibilities

1. Within the lifetime, copy the complete pinned Python runtime (preserving modes
   and internal links) into the scanned owned subtree, then use its executable
   for UV and every native helper/backend/consumer. Record native Git HEAD and
   complete clean status. Query UV workspace metadata
   with the frozen lock and pinned Python; preserve the complete original response.
2. Prepare owned planning tools with root-dev frozen sync excluding workspace
   products, then frozen shared/noneditable sync selecting both existing `dev`
   and `workflow-delivery-python` groups. Both
   consume the existing synchronized declarations and lock; no extra dependency
   manifest. Query the selected source directory through maintained Hatchling
   metadata and nbgv-python's official NBGV projection.
3. Invoke the temporary planning harness against those original responses. Launch
   the actual private CLI with its exact complete plan/request and fresh external
   scratch. It performs at most 15 UV/Python operations: five distribution-set
   operations, two contents inspections, three original-wheel consumer operations
   and five original-sdist consumer operations. The sdist rebuild is offline and
   Git-free, with prepared noneditable backend/plugin distributions. No original
   archive, source pyproject or version metadata is rewritten to force success.
4. After all four required results pass, query native installed distribution/file/
   direct-url/module-origin facts in the execution tools and each clean consumer.
   Preserve complete result/command/termination/stdout/stderr facts, original
   archives and separately identified rebuilt wheel; recheck complete checkout
   HEAD and status on success and failure before owned cleanup. The actual native
   member list remains the roster.

UV owns group/workspace/frozen installation and PEP517 dispatch. Maintained
backend/plugin interfaces own metadata/version. Python's maintained packaging,
installed metadata/import interfaces and standard archive readers expose facts;
the registered quality implementation retains actual product payload/API checks.

## Environment and Effects

Start each outer/native child with the explicit minimal environment in the exact
operator/packet. PATH=/usr/bin:/bin, LANG/LC_ALL=C.UTF-8; newly owned HOME, XDG
config/cache/data, TMPDIR, UV cache, NuGet packages and Dotnet CLI home; no inherited
credential, `UV`/`PIP`/`PYTHON`/`PYTEST`/Git/feed/proxy/preload overrides. Python user sites
are disabled and helper calls use -I; no PYTHONPATH/source fallback. -I ignores
Python bytecode environment flags, so all native tools use the complete owned
Python runtime rather than a shared stdlib. The readonly outer transport and
cleanup bootstrap use the pinned original interpreter with native -I -B; cleanup
removes the owned runtime only after native tools stop. Installed observers retain
base executable, base prefix and maintained sysconfig stdlib coordinates to check
actual relocation. This source-supported closure is not observed relocation. UV disables
Python downloads/keyring, selects the public PyPI default index, native TLS and
first-index policy. Repository locked public distribution URLs remain native
installation inputs. Native download/build/subprocess traffic is delegated to
the maintained tools within the enclosing lifetime, not counted as operator API
calls or claimed to be zero egress. TLS verification stays enabled.

Official NBGV uses the retained read-only prepared distribution through the supported
shlex-compatible `dotnet exec --fx-version 10.0.12 <nbgv.dll>` command. The private
application and harness use the read-only prepared .NET runtime. Only Python is
copied into the newly owned subtree; NBGV and .NET remain retained prepared tools. Git ignores system/user
configuration and prompts. No host settings, shared cache, repository credentials
or global tool installation is modified. This is a trusted-code local experiment,
not a hostile-code sandbox or universal subprocess/network containment guarantee.

## Bounds, Stop and Cleanup

One main lifetime and at most two fresh diagnostics, total at most 1,800 seconds;
each at most 600 seconds including evidence retention/stop/owned cleanup. Every
failed or ambiguous launch spends its lifetime/calls. No automatic retry. Root
records the campaign's cumulative receipts before another launch; missing/partial
receipts, remaining live children, unexplained changes or failed cleanup prevent
another launch. Each diagnostic requires independent classification of the prior
failure and a separately protected exact packet/query. The first independently
accepted success terminates all unused diagnostics. This is reviewed operator
admission, not an application-maintained dynamic policy file.

The success recipe contains 22 top-level UV/Python calls: four planning calls,
15 execution calls and three inventories. A 32-call lifetime ceiling leaves at most
10 extra call slots. They require separately described and protected diagnostic
coordinates; no such extra calls are admitted by this main packet. Reserve calls before dispatch; the CLI reserves its entire 15-call maximum
before launch and records actual returned command count without refunding uncertain
starts. Ordinary Git/planning/CLI invocations and one cleanup Python child are
separately visible rather than hidden in 22. Each native command receives 60 seconds;
the enclosing CLI remains within the inclusive lifetime, with 30 seconds reserved
for terminal Git readback/retention/cleanup. Final native HEAD and complete status
readbacks run on both success/failure paths, each with at most 10 seconds including
stop, retaining request/result/unavailable errors; ten seconds remain reserved
for cleanup. A changed HEAD, dirty status or unavailable readback prevents capture
success without masking an earlier failure. Git/materialization/NBGV/backend children remain under
their parent and enclosing process-group/time bound.

The source-reviewed supervisor creates a separate process group, retains requests
before start, captures each outer stream to at most 32 MiB and retains terminal
receipts on failures. It samples nonfollowing owned state at one-second intervals
and Linux process-group membership at 250 ms while quiet children execute. Observed
thresholds: 4 GiB logical file/link bytes, 40,000 entries including baseline checkout,
256 process-group members; three retained lifetimes at most 12 GiB thresholded state.
Native interpreter/venv symlinks count their link bytes without traversing targets.
Normal enumerated descendant disappearance during lstat/readlink/scandir is
tolerated without retry; explicit missing roots, permission errors and special
owned files still stop capture. These are sampled limits with scan/scheduling
lag, not strict kernel disk/process quotas. No containment of children creating
new sessions is claimed; trusted inspected tools are the premise.

Timeout, cancellation, nonzero/start failure, output/state/process overflow,
unexpected native contract/identity/output, omitted/failed check, checkout mutation,
remaining live child, evidence preservation or cleanup failure is terminal. Stop
the exact owned process group and record remaining zombie/live membership within
the remaining deadline. On failed capture retain partial raw bytes and owned
state for independent classification; no automatic repair. On complete capture,
copy and hash-check both original distributions, retain inventories/results/raw
observations and the separate rebuilt wheel, then invoke one bounded stdlib
fd-based nonfollowing cleanup of only the freshly created `owned` subtree.
Keep the frozen checkout, packet, receipts, original evidence and archives. No
external link target, host/shared-cache or historical evidence is removed.
