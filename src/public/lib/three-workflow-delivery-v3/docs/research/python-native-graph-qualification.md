# Current-Tool Native Python Graph Qualification

## Question and Authority

This protocol qualifies the actual managed collector against the current
repository lock and prepared tools. It implements the accepted
[Python integration order](../migration-strategy.md#python-planning-integration-and-later-caller-cutover)
within the accepted [Delivery Wave](../../../../../../docs/delivery-wave.md).
Exact source, preparation and protocol review and protected delivery must complete
before the first query. This record currently contains no runtime outcome.

The stopped [primitive campaign](python-native-planning.md#primitive-native-observation)
and its expired reserves remain unchanged. This new subject is complete production
collector composition at PyPA build 1.6.1 and lock revision 5, with actual complete
native membership and caller operations. It does not repeat that primitive suite.

## Operations and Native Authority

Run the real `PythonNativeGraphReader` once per endpoint through the harness.
The first endpoint uses ordinary dev contexts; the second uses no-dev contexts.
Each collector's single metadata answer supplies the complete member roster to
its synchronous caller factory. Construct directory operations from those native
member directories plus root, sorted and deduplicated, and singleton package
operations from sorted native member names at root. Use `context-N` and
`package-N` only as request IDs. Do not maintain another member/target roster or
interpret group/default/marker/extra semantics in the harness.

The actual managed commands are limited to:

1. `uv workspace metadata --frozen --python <clean-python>`;
2. `<clean-python> <passive.py> <native-context>` for every member plus root;
3. `<clean-python> <passive.py> --configuration-only <complete-contexts>` before
   each supplement;
4. `<native-helper> <fresh-request.json>` for ordered bootstrap and activity.

Bootstrap supplies all passive contexts with no operation/marker/constraint
requests. The actual production planning component then forms the complete
activity request from native coordinates and unchanged strings. Native UV owns
source lowering, interpreter, group, default, marker and extra answers. Its
internal interpreter operation uses the same exact supplied clean Python. PyPA
`ProjectBuilder.build_system_requires` and maintained `PluginConfig` supply
passive requirements and coordinates; no backend or version generator runs.

The finite values are:

- `PYTHONNOUSERSITE=1`, `PYTHONSAFEPATH=1`, `PYTHONDONTWRITEBYTECODE=1`;
- `PYTHONPATH` containing only the endpoint maintained plugin and the exact
  extracted dependency sources;
- exact `DOTNET_ROOT`, `DOTNET_CLI_TELEMETRY_OPTOUT=1` and
  `DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1`.

Do not inherit UV/PIP/PYTEST/proxy/credential/preload settings. Native ambient
user/system settings returning Some or an error stop the default request; do not
repair host settings or bypass their semantics. Prepare distinct empty bootstrap
and activity scratch directories before invocation.

Effects are local reads and generation-owned cache/configuration/temp/scratch
writes. There is no sync, install, resolve, download, build/backend/version
execution, registry operation, publication, hosted dispatch, credential
acquisition, Environment/access change or shared-state cleanup. The native helper
uses empty credentials and its reviewed guarded lowering boundary. Process and
environment isolation is not an OS/network sandbox; it establishes neither zero
egress nor universal containment.

## Limits and Terminal Handling

Allow one main attempt and at most two diagnostics. Each diagnostic requires an
independently triaged failure or rejected interpretation and a fresh reviewed
packet and owned state. No automatic retry. Stop at the first independently
accepted success or exhausted/unsafe bounds. Captured transport is not acceptance.
The packet role records this procedure; it does not prove reviewer authorization.

Each managed native command has a 30-second deadline. The harness admits at most
64 native members and 70 managed commands per endpoint: exactly two endpoint
captures and at most 140 managed commands per attempt. Unknown executables or
necessary unsupported shapes stop before another stage.

Charge active capture, final observations, process stop and later owned cleanup
to at most 1200 seconds per attempt and 3600 cumulatively. Reserve 30 seconds for
owned cleanup inside the attempt budget, with five seconds for process stop
inside each supervisor deadline. Human review/idle retention is not executable
time and cannot refill any budget. The supervisor records monotonic elapsed after
bounded final observations. Incomplete receipts or missing/failed cleanup prevent
a diagnostic; cleanup elapsed is added before another attempt.

Retain at most 32 MiB per outer stream; preserve the available prefix on overflow.
The production runner's smaller individual capture remains unchanged. Sample
current owned state plus endpoint baseline against 4 GiB/40000 entries, and all
retained attempts plus endpoints against 12 GiB/120000 entries. Scan incrementally
with a supplied monotonic deadline, retaining partial counters/errors. Observe
state while quiet children run. These are detect-and-stop limits, not instantaneous
OS quotas; checks between entries do not preempt a stalled filesystem call.

Stop the owned Linux process group on every terminal path, including parent
success, using the platform's group/signal semantics. Preserve original leader
result/error and separate stop outcome. Unresolved stop invalidates capture.
Escaped sessions, arbitrary hostile children and Windows are outside this promise.

Create a running receipt before launch. Preserve original requests, environment,
stdout/stderr, results, termination, elapsed and state/stop errors. Final state
failure must not suppress the attempt receipt or replace its original error. A
start, timeout, cancellation, capture, state, transport, unexpected command,
endpoint mutation or cleanup failure consumes the attempt and stops. Do not
relabel it as successful native collection or silently replay it.

## Evidence, Interpretation and Cleanup

Before invocation, retain clean endpoint Git identities/status, absent project
environments, source/tool/runtime/dependency identities and original build
receipts. After group stop, independently inspect original command requests and
answers, complete graph/terminal outputs, endpoint Git status and project
environment absence. Read-only interpretation does not issue additional native
collector/helper queries or introduce another UV implementation.

Check complete native root/member/passive contexts, exact operation/interpreter
identities, ordinary versus no-dev activity, build-only smoke and ordinary-plus-
build sample consumers of the maintained plugin, native local source joins,
marker/extra/constraint answers, plugin working/generated coordinates and complete
configuration inputs. Preserve input-only and tableless contexts. Unexpected or
missing required identities/relations are terminal findings, not a reason to add
parallel semantics or weaken coverage.

Retain original evidence before making separately sanitized public copies. The
independent audit decides whether the exact collector observation is sufficient;
source findings, observations and inferences remain distinct. Nineteen controlled
supervisor tests establish only synthetic supervisor behavior, not this native
observation.

After independent interpretation and original evidence retention, invoke the
reviewed supervisor's cleanup entry once for that attempt. Its bounded isolated
standard-library child removes only `endpoint-1`/`endpoint-2` generation-owned
`environment`, `bootstrap` and `activity` directories. Preserve native/outer
receipts, requests, graph, packet and original evidence. Preserve endpoint source
snapshots, shared tools/configuration and historical campaigns. Original cleanup
request/output/termination/elapsed remain retained. Cleanup failure stops later
launches; unused time does not add an attempt.

## Outcome and Recheck

No actual collector query has executed under this protocol yet. Qualified success
would establish only complete current-tool collector composition on the recorded
Linux host. It would not establish native pytest qualification, managed NBGV
query binding, quality preset expansion, preparation/install/build/check execution,
package consumers, full paired caller behavior, caller cutover, Windows or release
readiness.

Recheck affected source/operation contracts when tools, lock format, source or
necessary environment changes, or the next integration review relies on them.
The author evaluates affected interfaces; independent domain/evidence review
checks the result. Necessary material effects or product changes outside this
protocol stop for owner disposition. Routine repetitions within its accepted
finite boundary need no repeated owner approval.
